`OpenReaderWithLimits` is additive and accepts opt-in source-byte, entry-count, per-part and total-inflated-byte limits. Source budget is checked before ZIP parsing; remaining budgets are checked before payload inflation. Existing OpenReader uses zero budgets for compatibility. Negative sizes/budgets are argument errors. Resource refusal is `*Refusal` kind `resource_limit`. Payload reads are capped at declared size plus one, enforce declared size and return typed `invalid_package` failures for corrupt streams/CRC.

Entry count is checked after archive/zip parses the central directory; callers needing bounded metadata parsing must also set a finite source limit and isolate workers. Local/central-header consistency and overlap validation are not yet implemented. The zero-budget compatibility path is not a secure default for hostile unlimited inputs.
