## Batch 009: namespace-aware lossless leaf editing

Parent: bf9fe81. Red/green commands: `GOMAXPROCS=2 go test -p 2 ./internal/losslessxml ./pkg/packaging`, followed by all acceptance-module tests with the same limits. Initial compile-valid parser shell fails namespace/leaf assertions in 009-red.log; implementation passes 009-green.log. Thirty-four expanded native Gherkin cases now pass. No individual test runs.

New internal immutable XML snapshot records expanded element/attribute names, lexical content offsets and parent ownership without reserializing markup. It rejects undeclared/reserved prefixes, duplicate expanded attributes, mismatched lexical end QNames, multiple roots and directives. Atomic plain-text leaf splices preserve every unrelated byte, including namespace declarations, unknown elements/attributes, comments, quote choices and QName-valued attributes. No-op retains entities/CDATA. Foreign/duplicate targets, mixed markup, invalid text and self-closing insertions refuse. Source and returned attribute slices are isolated.

Scope: UTF-8 and XML namespace 1.0-style prefix rules, bounded depth 512. This is an internal text-leaf primitive, not a generic subtree editor or OOXML schema validator. Format ownership, revision/protection, field and whitespace semantics need separate adapters. B03 is partial until these integration checks pass. Independent read-only review found ZIP descriptor-signature ambiguity and missing first-offset checks for later regression batches; Windows replacement behaviour remains explicitly uncertified, not assumed broken from review alone.
